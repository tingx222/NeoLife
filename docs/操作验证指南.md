## 3. 登录并准备接口验证变量

浏览器登录会把token放在sessionStorage，PowerShell请求不会自动共享该登录态。可在浏览器开发者工具中读取你自己的`sessionStorage.getItem('token')`，仅复制到本机终端；也可按下面方式单独登录：

```powershell
$api = 'http://localhost:8080/api'
$phone = Read-Host '输入你的测试手机号'
Invoke-RestMethod -Method Post -Uri "$api/user/code?phone=$phone"
$code = Read-Host '从后端开发日志输入验证码'
$loginBody = @{ phone=$phone; code=$code } | ConvertTo-Json
$loginResult = Invoke-RestMethod -Method Post -Uri "$api/user/login" -ContentType 'application/json' -Body $loginBody
if (-not $loginResult.success) { throw $loginResult.errorMsg }
$headers = @{ authorization = $loginResult.data }
Invoke-RestMethod -Uri "$api/user/me" -Headers $headers
```

预期：返回你的精简用户资料。验证码成功使用后会失效，再登录要重新获取。这里是开发日志验证码，没有真实短信。

本指南后续接口使用`$api`和`$headers`。JSON若含中文，统一用UTF-8字节，避免Windows编码差异：

```powershell
function Post-Json($path, $payload) {
    $json = $payload | ConvertTo-Json -Depth 12
    Invoke-RestMethod -Method Post -Uri "$api$path" -Headers $headers `
        -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($json))
}
```

## 4. 商户缓存与布隆过滤器

1. 首页应看到商户分类，打开一个真实商户，记录ID（以下假定1存在）。
2. 请求`Invoke-RestMethod "$api/shop/1"`，应返回商户数据。
3. 请求一个确定不存在的正整数ID，应返回`success=false`和店铺不存在。
4. 在已连接Redis的命令终端/RedisInsight中检查：

```text
EXISTS shop:bloom:v1
GET shop:bloom:v1:ready
GET cache:shop:1
```

预期：过滤器存在，ready为1，缓存含data和expireTime。过滤器约1%误判率，“不存在”不能单凭一次返回证明一定被Bloom拦截；应结合SQL日志或单元测试确认未回源。

### 冷缓存与逻辑过期验证（仅本地测试）

- 删除`cache:shop:1`这一个测试缓存，再访问真实商户，应该仍成功，并重建缓存。
- 不删除缓存，等待超过20秒后访问；应可返回旧值并触发异步刷新，再检查expireTime变新。
- 同时从多个标签页查询这个商户，检查没有持续报错。

这些操作只验证行为，不证明锁争用下的性能。不要删除Bloom、全部Redis数据或秒杀Key来模拟故障。新增商户需由项目接口写入；直接在DB插入会绕过Bloom维护，需要重启重建。

- [ ] 真实商户可查，不存在的商户被拒绝。
- [ ] 冷缓存可回源，逻辑过期后可刷新。

## 6. RabbitMQ下单闭环

```powershell
$submitted = Invoke-RestMethod -Method Post -Uri "$api/voucher-order/seckill/$voucherId" -Headers $headers
if (-not $submitted.success) { throw $submitted.errorMsg }
$orderId = [string]$submitted.data
for ($attempt=0; $attempt -lt 20; $attempt++) {
    $orderResult = Invoke-RestMethod -Uri "$api/voucher-order/$orderId" -Headers $headers
    if (-not $orderResult.success) { throw $orderResult.errorMsg }
    if ($orderResult.data.state -eq 'SUCCESS') { break }
    Start-Sleep -Seconds 1
}
$orderResult | ConvertTo-Json -Depth 6
Invoke-RestMethod -Uri "$api/voucher-order/of/me" -Headers $headers
```

预期：提交返回受理订单号，查询最终SUCCESS；SUCCESS表示已创建未支付订单，不是支付成功。浏览器“我的订单”也应能看到它。

同一账号再抢同一券应失败。另用两个不同测试账号各抢一次，最终共3单，第4个账号应库存不足。账号登录方法相同，每个账号保存自己的headers，不要把同一个Token重复当作多个用户。

在数据库工具执行只读SQL，将示例123替换为本次券ID：

```sql
SELECT voucher_id, stock FROM tb_seckill_voucher WHERE voucher_id = 123;
SELECT id, user_id, voucher_id, status FROM tb_voucher_order WHERE voucher_id = 123;
SELECT user_id, COUNT(*) FROM tb_voucher_order
WHERE voucher_id = 123 GROUP BY user_id HAVING COUNT(*) > 1;
```

预期：创建3单后DB库存0、订单数3，最后的重复用户查询无记录；Redis活动库存也为0。Rabbit管理台主队列Ready/Unacked最终归零，死信不增加。消费很快时可能看不到队列积压，这是正常现象。

### 如何证明消息确实经过RabbitMQ

仅看到订单落库不够：Stream-only模式也能落库。确认Rabbit启用、队列消费者存在，并观察管理台发布/投递/ACK统计随测试变化。需要更明确证据时，在本地对RabbitOrderTransport.publish、receive设置断点；不要在调试期间做压测。

链路应为：Lua预扣 → Stream出站记录 → Rabbit持久消息+确认 → Stream ACK → Rabbit消费 → DB事务提交 → 消费ACK。Stream仍存在是可靠投递设计，不是忘记切换Rabbit。

- [ ] 返回受理后最终落库成功。
- [ ] Rabbit发布/消费/ACK统计有变化。
- [ ] 一人一券、库存对账均正确。

## 7. 故障验证（仅本地专用测试活动）

### Broker暂时停止

```powershell
docker compose stop rabbitmq
```

用新测试券提交请求：Redis仍可先受理，订单可能持续PROCESSING，Stream Pending保留，后端有出站失败日志。不要不断重发同一笔请求。

```powershell
docker compose start rabbitmq
docker compose ps
```

等Broker恢复健康，再轮询原订单号，应最终落库且只扣一次DB库存。若进入死信，先分析原因，不要擅自补库存或删除标记。停止Broker可能需要等待发布确认超时和重连，不能要求瞬间恢复。

### 权限与无效请求

- 不带headers查询订单，应HTTP401。
- 账号B查询账号A的订单，应“订单不存在或无权查看”。
- MCP工具里伪造userId，不应切换服务端用户。
- 错误模型参数、过期Token，应返回受控错误。

消费数据库失败会NACK进入死信。优先通过测试模拟，不要关闭真实数据库或直接篡改业务库存。当前没有自动死信重放/库存补偿，PROCESSING不会自动变成FAILED。

## 8. 验证MCP工具（不花DeepSeek费用）

HTTP桥只用于stdio适配器，不是完整Streamable HTTP传输。先用PowerShell验证分发协议：

```powershell
Post-Json '/mcp' @{ jsonrpc='2.0'; id=1; method='initialize'; params=@{protocolVersion='2025-03-26'; capabilities=@{}; clientInfo=@{name='manual-check'; version='1.0'}} }
Post-Json '/mcp' @{ jsonrpc='2.0'; method='notifications/initialized' }
Post-Json '/mcp' @{ jsonrpc='2.0'; id=2; method='tools/list' }
Post-Json '/mcp' @{ jsonrpc='2.0'; id=3; method='tools/call'; params=@{name='search_shops'; arguments=@{keyword='茶'}} }
Post-Json '/mcp' @{ jsonrpc='2.0'; id=4; method='tools/call'; params=@{name='get_shop_vouchers'; arguments=@{shopId='1'}} }
Post-Json '/mcp' @{ jsonrpc='2.0'; id=5; method='tools/call'; params=@{name='get_my_order'; arguments=@{orderId=$orderId}} }
```

预期：initialize返回协议版本和tools能力；initialized是通知，202空响应；tools/list列出search_shops、get_shop_vouchers、get_my_order、get_faq；tools/call返回result.content中的text，不是普通接口的data。中文关键字可以替换为已有商户名称。

再验证真实stdio进程：

```powershell
$env:HMDP_USER_TOKEN = $headers.authorization
$env:HMDP_MCP_URL = "$api/mcp"
@'
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"manual-check","version":"1.0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/list"}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_faq","arguments":{"topic":"login"}}}
'@ | python scripts/mcp_server.py
Remove-Item Env:HMDP_USER_TOKEN
```

预期stdout只有3条JSON-RPC响应（通知不返回），没有Spring日志或Token。注意这里给的是本项目登录Token，不是DeepSeek密钥。stdio适配器只允许loopback地址。Token过期后需重新登录。

- [ ] 工具发现、调用和stdio通道都可用。
- [ ] 订单工具权限隔离正确。

## 11. 排错速查

| 现象 | 优先检查 |
|---|---|
| 首页分类空白/502 | 新后端是否启动、Nginx是否转发同一端口、DB/Redis可达 |
| Docker命令找不到 | 重开终端或补Docker resources/bin到PATH |
| Rabbit认证失败 | .env和Java配置是否一致；已有volume中的用户密码不会随.env自动改变 |
| 日志显示guest认证失败，但本地配置是hmdp | 执行python scripts/Configure-RabbitLocal.py生成被忽略的config/application-rabbit.properties；Spring Boot 2.3的profile配置可能覆盖普通配置；确认IDEA工作目录为项目根目录后停止并重新运行 |
| 订单长期PROCESSING | Broker健康、主队列消费者、Stream Pending、死信队列、DB事务日志 |
| 下单成功却没Rabbit统计 | 是否还有旧消费者或Rabbit开关未启用 |
| MCP返回401 | 登录Token是否失效，不能用DeepSeek密钥代替 |
| MCP返回403 | 私有HTTP桥拒绝Origin头，使用stdio适配器或本地脚本 |
| 客服密钥无效/余额不足 | 本地DeepSeek配置、账户余额，修改配置后重启Java |
| 端口占用 | 确认具体PID和启动来源，不结束所有Java进程 |
| Nginx unknown directive，开头出现“锘”等乱码 | 旧安装脚本在Windows PowerShell 5.1写入UTF-8 BOM；使用已修复脚本重新安装配置，不需要重新打包Java |
| Nginx OpenEvent ngx_reload 找不到 | 通常是Nginx未运行、旧PID文件或运行实例不匹配；新版安装脚本在没有Nginx进程时会自动启动，有进程但实例不匹配时需核对路径和PID |
